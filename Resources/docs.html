Macapad

Control your Mac from a phone, a tablet, or anything that can make a web request. Pair this browser and every example on this page runs for real.

Not connected

Connect

Pick a Mac to pair with. You’ll confirm on the Mac, then this browser keeps its own token.

QR pairing

In Macapad’s menu bar, choose Pair with QR Code…. An app with a camera scans it and is paired straight away, with no prompt on the Mac: being able to see the screen is the proof. Each code works once, and only while that window is open.

The code holds a link with everything needed to connect:

macapad://pair?v=1&id=<mac id>&name=<mac name>&key=<one-time key>
  &url=http://192.168.1.20:7317
  &url=http://100.101.102.103:7317

There’s one url per address the Mac can be reached at, best first (local network, then Tailscale). Values are percent-encoded (except : and /), so any URL parser reads them back. Use the first url that answers GET /api/health, then trade the key for a token:

POST <url>/api/pair/qr
{"key": "<one-time key>", "name": "Kitchen iPad", "app": "archersdesk"}

→ {"status": "approved", "token": "…", "device": {…}, "mac": {"id": "…", "name": "…"}}

The token is shown once, so keep it. A key that was already used or has expired gets 410. To pair this browser from a QR code, use Scan a QR code above (needs HTTPS or localhost for the camera) or paste the link from the window’s Copy Pairing Link button into Type an address.

Code pairing

For devices without a camera. The Mac asks before allowing anything.

  1. POST /api/pair with {"name": "Kitchen iPad", "app": "archersdesk"}. You get {"id", "code", "expiresIn", "mac"}. Show the 4-digit code to the person.
  2. The Mac shows the device’s name and the same code, with Allow and Don’t Allow.
  3. Poll GET /api/pair/<id>?wait=25. Each call waits up to 25 seconds, then returns pending, approved (with token and device), denied or expired.

Requests expire after two minutes. A device can only have one waiting at a time, and the Mac holds at most three.

Finding Macs

On the local network Macapad advertises _macapad._tcp over Bonjour, with id, name and v in its TXT record. Tailscale has no multicast: list your devices with tailscale status --json and call /api/health on each. A Mac that lets devices find it answers with a mac field. The same Mac found both ways has the same mac.id.

Steps

Everything the Mac can do is a step, written as {"type": …}. A request runs a list of steps in order and stops at the first one that fails.

Pair with a Mac to try these.

keystroke takes modifiers (cmd shift opt/alt ctrl fn) plus one key: a–z, 0–9, punctuation, f1–f20, arrows (left right up down), space return tab esc delete forwarddelete home end pageup pagedown. Keys are positions on a US keyboard. media steps are real media-key presses, so they control whatever is playing.

Actions

An action is a named list of steps. Run one with {"type": "action", "id": "reload"}. Macapad has built-ins for media, the system, windows, browsers and editing, and you can save your own with POST /api/actions (stored in ~/.macapad/actions.json). Ids are lowercase letters, numbers and dashes. Actions can run other actions, up to 4 deep.

{"id": "reload", "name": "Reload", "icon": "refresh", "category": "browser",
 "steps": [{"type": "keystroke", "keys": "cmd+r"}], "custom": false}

icon is a Material Symbols name, a hint for frontends.

On your Mac

Pair with a Mac to see its actions and tap one to run it.

HTTP API

Send the token as Authorization: Bearer <token>. Health and pairing don’t need one. Bad requests return a 4xx with {"error": {"message": "…"}}.

Pair with a Mac to try the GET routes.


      
curl -X POST http://localhost:7317/api/run \
  -H "Authorization: Bearer $(cat ~/.macapad/token)" \
  -H "Content-Type: application/json" \
  -d '{"steps":[{"type":"media","key":"playPause"}]}'

    


    

      
WebSocket

      
For a frontend that stays open, /api/ws?token=<token> is quicker than a request per press. Browsers can’t set headers on a WebSocket, so the token goes in the URL.

      
    
        
  • Send {"type": "run", "ref": "<anything>", "steps": [...]}. You get back {"type": "result", "ref", "ok", "error"}.
    • 
        
  • Send {"type": "ping"} every ~25 seconds so proxies don’t close the connection. You get {"type": "pong"}.
    • 
      

      
If a device is removed in Settings, its open connection closes the next time it sends anything.

      
const ws = new WebSocket(`${base.replace(/^http/, "ws")}/api/ws?token=${token}`);
ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  if (msg.type === "result" && !msg.ok) alert(msg.error);
};
ws.onopen = () => {
  ws.send(JSON.stringify({ type: "run", ref: "skip", steps: [{ type: "media", key: "next" }] }));
};

Tailnet over HTTPShttps://<mac>.<tailnet>.ts.net after tailscale serve --bg 7317

      

      
A page served over https:// has to call the HTTPS address. Browsers block HTTPS pages from calling plain http addresses.

      
Macapad’s Settings choose which networks may connect and which may find the Mac and pair. Programs on the Mac itself are always allowed; anything else from a network that’s turned off gets 403. Pairing is never allowed from the internet.

      
Tokens

      
    
        
  • Device tokens come from pairing. Each device has its own, and removing one in Settings cuts off only that device.
    • 
        
  • The owner token is in ~/.macapad/token (menu bar: Copy API Token), for scripts and frontends set up by hand. It has full access.
